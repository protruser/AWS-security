기존 AWS Security Monitoring Center 대시보드 디자인을 다음 요구사항에 맞게 수정해 주세요.

## 1. 기본 방향

현재 화면의 다음 요소는 그대로 유지합니다.

* 흰색과 파란색 중심의 엔터프라이즈 보안관제 디자인
* 상단 헤더
* 왼쪽의 인터랙티브 AWS 아키텍처 관제 맵
* 공격 경로 및 자산 상태 표시
* 오른쪽의 조치 관리 영역
* 전체 화면의 왼쪽 약 2/3, 오른쪽 약 1/3 비율

과도한 네온이나 어두운 사이버펑크 스타일을 사용하지 말고, 국내 대기업 IT 운영 시스템처럼 밝고 전문적인 분위기를 유지해 주세요.

## 2. 상단 헤더 수정

현재 `자동 갱신 5초`로 표시된 부분을 다음과 같이 변경해 주세요.

* 자동 갱신 주기: 1분
* LIVE 표시 유지
* 마지막 갱신 시각 표시
* `자동 갱신 ON` 버튼 유지
* 사용자가 자동 갱신을 끄거나 다시 켤 수 있도록 구성

1분마다 데이터가 갱신될 때 마지막 갱신 시각과 아키텍처 상태가 자연스럽게 변경되도록 표현해 주세요.

## 3. 왼쪽 상단: 아키텍처 관제 맵

현재 아키텍처 관제 맵의 구조와 크기는 최대한 유지합니다.

다음 자산이 연결된 상태로 표시되어야 합니다.

* 일반 사용자
* 공격자 서버
* 쇼핑몰용 AWS WAF
* 쇼핑몰용 ALB
* K3s nginx Reverse Proxy
* Flask App Server
* 쇼핑몰 MySQL
* 관리자용 AWS WAF
* 관리자용 ALB
* Dashboard EC2
* Lambda A
* Lambda B
* 보안결과 MySQL
* Security Hub
* GuardDuty
* Inspector
* Access Analyzer
* Macie
* CloudTrail
* CloudWatch
* VPC Flow Logs
* WAF Logs

보안 이벤트를 선택하면 해당 공격 경로만 강조하고, 관계없는 연결선은 흐리게 표시해 주세요.

예를 들어 SQL Injection 이벤트를 선택하면 다음 경로를 빨간색으로 강조합니다.

공격자 서버
→ 쇼핑몰용 WAF
→ 쇼핑몰용 ALB
→ K3s nginx
→ Flask App Server

탐지한 서비스에는 `탐지 위치`, 공격받은 서버에는 `영향 대상` 배지를 표시해 주세요.

## 4. 왼쪽 하단: 7개 공격 시나리오 카드 개편

기존처럼 7개의 카드를 모두 동일한 게이지로 표현하지 마세요.

각 시나리오의 데이터 성격에 따라 다음 네 가지 UI 형식으로 구분해 주세요.

카드 크기를 기존보다 높고 넓게 만들어 화면 아래쪽의 불필요한 빈 공간을 줄여 주세요.

카드 영역은 다음과 같은 2열 Grid로 구성합니다.

* 1행: SQL Injection / XSS
* 2행: 디렉터리 서치 / 로그인 무차별대입
* 3행: 포트 스캔 / 탈취 자격증명
* 4행: 취약 컨테이너 이미지 — 전체 너비 사용

카드 사이의 간격은 12~16px 정도로 유지하고, 카드 내부 여백은 충분히 확보해 주세요.

### 4-1. 이벤트형 카드

대상:

* SQL Injection
* XSS

형태:

* 상태 배지
* 최근 차단 건수
* 최근 차단 시각
* 최근 Payload 한 줄 미리보기
* 탐지 서비스명
* 작은 Shield 아이콘

SQL Injection 예시:

* 제목: SQL Injection · WAF
* 상태: 공격 탐지·차단됨
* 최근 차단 3건
* 시각: 14:32:07
* Payload: `' OR '1'='1`
* 상태 색상: Red

XSS 예시:

* 제목: XSS · WAF
* 상태: 정상 방어 중
* 최근 차단 0건
* 최근 24시간 이내 탐지 없음
* 상태 색상: Green

이 두 카드에는 게이지나 차트를 사용하지 마세요.

### 4-2. 트래픽 임계치형 카드

대상:

* 디렉터리 서치
* 로그인 무차별대입

형태:

* 원형 진행률 게이지
* 현재 요청 수 / 임계치
* 측정 시간 범위
* 임계치 초과 시 적용되는 정책
* WAF Rate-based Rule 표시

디렉터리 서치 예시:

* 제목: 디렉터리 서치 · WAF Rate Rule
* 게이지: 80%
* 현재 수치: 120 / 150
* 설명: 5분당 요청
* 상태: 주의
* 색상: Orange

로그인 무차별대입 예시:

* 제목: 로그인 무차별대입 · WAF Rate Rule
* 게이지: 100%
* 현재 수치: 50 / 50
* 설명: 임계치 초과
* 상태: WAF BLOCK 적용 중
* 색상: Red

게이지는 이 두 카드에만 사용해 주세요.

### 4-3. 이상행위 탐지형 카드

대상:

* 포트 스캔
* 탈취 자격증명

형태:

* 상태 배지
* GuardDuty Finding Type
* 이상행위 판단 근거 한 줄
* Source IP 또는 사용자 정보
* 최근 탐지 시각
* 작은 GuardDuty 아이콘

포트 스캔 예시:

* 제목: Port Scan · GuardDuty
* 상태: 이상행위 탐지
* Finding: Recon:EC2/Portscan
* 근거: 23개 포트 프로브 감지
* Source IP: 203.0.113.45
* 색상: Red

탈취 자격증명 예시:

* 제목: 탈취 자격증명(퇴사자) · GuardDuty
* 상태: 이상행위 탐지
* Finding: CredentialAccess:IAMUser
* 근거: 평소 사용하지 않는 리전에서 AWS API 호출
* 호출 API: s3:ListBuckets 외 3건
* Access Analyzer 정보: 키 마지막 사용 92일 전
* 색상: Red

이 두 카드에는 게이지를 사용하지 마세요.

### 4-4. 정적 스캔 결과형 카드

대상:

* 취약 컨테이너 이미지

전체 너비를 차지하는 가로형 카드로 구성해 주세요.

형태:

* Inspector 아이콘
* 심각도별 CVE 개수
* 가로 스택바
* 스캔 대상 이미지
* 마지막 스캔 시각
* 상세 보기 버튼

예시:

* 제목: 취약 컨테이너 이미지 · Inspector
* Critical 1
* High 3
* Medium 2
* 대상 이미지: shopping-flask:latest
* 마지막 스캔: 2026.09.18 14:20

가로 스택바 색상:

* Critical: Red
* High: Orange
* Medium: Yellow
* 나머지 영역: Light Gray

시계열 그래프나 실시간 게이지를 사용하지 마세요.

## 5. 공격 시나리오 카드 인터랙션

각 카드를 클릭하면 다음 동작을 수행해 주세요.

1. 상단 아키텍처에서 관련 자산과 공격 경로 강조
2. 오른쪽 패널에 해당 이벤트 상세 정보 표시
3. 선택된 카드는 파란색 또는 심각도 색상의 테두리 적용
4. 나머지 카드는 약간 흐리게 표시
5. 다시 선택하면 상세 상태 해제

예시:

* SQL Injection 카드 선택 → 공격자, WAF, ALB, K3s, Flask 강조
* 포트 스캔 카드 선택 → 공격자, VPC Flow Logs, GuardDuty, 대상 EC2 강조
* 취약 이미지 카드 선택 → Inspector, ECR, K3s 강조
* 탈취 자격증명 카드 선택 → IAM 사용자, CloudTrail, GuardDuty 강조

## 6. 오른쪽 영역 전체 구조

오른쪽 1/3 영역은 화면 높이를 기준으로 위아래 두 부분으로 나눠 주세요.

* 상단 약 50%: 조치 필요 및 탐지 이력
* 하단 약 50%: 보안 챗봇

두 영역 사이에는 얇은 구분선 또는 드래그 가능한 Divider를 배치해도 됩니다.

오른쪽 영역 전체 너비와 기존 카드 크기는 현재 디자인과 비슷한 수준을 유지해 주세요.

## 7. 오른쪽 상단: 조치 필요 및 탐지 이력

상단 패널에는 다음 탭을 유지합니다.

* 조치 필요
* 탐지 이력

탭 헤더는 고정하고, 하단 카드 목록만 내부 스크롤되도록 만들어 주세요.

스크롤 영역에 다음 요소를 적용해 주세요.

* 고정 높이
* 내부 Vertical Scroll
* 얇고 눈에 잘 띄지 않는 스크롤바
* 카드 간격 10~12px
* 새로운 Critical 이벤트는 가장 위에 배치
* 현재 선택된 이벤트 카드는 강조 표시
* 목록을 스크롤해도 탭 헤더는 상단에 고정

### 조치 필요 카드

각 카드에는 다음 정보를 표시해 주세요.

* 심각도
* 이벤트명
* 영향 자산
* 탐지 서비스
* 탐지 시각
* 조치 대기 시간
* 현재 상태
* 조치 승인 버튼
* 예외 처리 버튼

예시:

* Critical / SQL Injection 반복 요청 / Flask App Server
* High / ECR 이미지 취약 패키지 발견 / K3s
* High / S3 버킷 외부 공개 설정 / S3

### 탐지 이력

테이블 또는 리스트 형태로 구성합니다.

* 탐지 일시
* 공격 유형
* 심각도
* 탐지 서비스
* 영향 자산
* 차단 여부
* 조치 상태

## 8. 오른쪽 하단: 보안 챗봇

오른쪽 아래 절반에는 `보안 분석 어시스턴트` 챗봇을 배치해 주세요.

챗봇은 보안 조치를 임의로 실행하는 기능이 아니라, 현재 탐지된 이벤트와 로그를 쉽게 분석하도록 돕는 보조 도구입니다.

### 챗봇 헤더

* 아이콘
* 제목: 보안 분석 어시스턴트
* 상태: 온라인
* 새 대화 버튼
* 패널 확장 버튼

### 기본 안내 문구

`탐지된 이벤트, 원본 로그 또는 권장 조치에 대해 질문해 보세요.`

### 추천 질문 버튼

* 이 이벤트를 요약해 줘
* 왜 Critical인가요?
* 관련 로그를 설명해 줘
* 권장 조치가 무엇인가요?
* 서비스 영향이 있나요?
* 비슷한 탐지 이력을 찾아줘

### 대화 영역

대화 메시지가 많아질 경우 챗봇 내부에서 세로 스크롤되도록 구성해 주세요.

사용자가 아키텍처 자산이나 공격 시나리오 카드를 선택하면 챗봇 상단에 Context Chip을 표시합니다.

예시:

* 선택 이벤트: SQL Injection
* 대상 자산: Flask App Server
* 탐지 서비스: AWS WAF
* 심각도: Critical

### 챗봇 응답 예시

사용자:

`이 SQL Injection 이벤트를 요약해 줘.`

챗봇:

`203.0.113.45에서 /api/products 경로로 SQL Injection 패턴이 포함된 요청이 3회 발생했습니다. AWS WAF가 요청을 차단했으며, Flask App Server까지 전달된 요청은 없습니다. 동일 IP의 반복 요청 여부를 추가로 확인하는 것을 권장합니다.`

응답 하단에는 다음 버튼을 제공합니다.

* 관련 로그 보기
* 공격 경로 강조
* 권장 조치 보기
* 조치 요청에 추가

챗봇에서 직접 자동 조치를 실행하지 않으며, 실제 조치는 반드시 별도의 `조치 승인` Modal을 거치도록 구성해 주세요.

### 챗봇 입력 영역

* 메시지 입력창
* 전송 버튼
* 선택 이벤트 첨부 버튼
* 로그 첨부 버튼
* Placeholder: `보안 이벤트 또는 로그에 대해 질문하세요`

## 9. 조치 승인 Modal

조치 승인 버튼을 누르면 다음 내용을 보여주는 Modal을 표시해 주세요.

* 조치 대상
* 이벤트명
* 현재 설정
* 변경될 설정
* 예상 서비스 영향
* 실행 방식
* 롤백 가능 여부
* 승인자
* 취소 버튼
* 조치 실행 버튼

실행 방식은 대상에 따라 구분합니다.

* EC2, K3s, nginx, Flask: Lambda Remediation → SSM
* WAF, Security Group, S3: Lambda Remediation → AWS API

## 10. 상태별 화면 Variant

다음 화면 상태를 함께 제작해 주세요.

1. 모든 자산이 정상인 기본 관제 화면
2. SQL Injection Critical 이벤트가 선택된 화면
3. 로그인 무차별대입 임계치가 100%인 화면
4. 조치 필요 목록을 스크롤한 화면
5. 탐지 이력 탭이 선택된 화면
6. 보안 챗봇에 SQL Injection 이벤트가 연결된 화면
7. 조치 승인 Modal이 열린 화면

전체적으로 상단 아키텍처 관제 맵, 하단의 데이터 성격별 시나리오 카드, 오른쪽의 스크롤 가능한 조치 목록과 보안 챗봇이 하나의 자연스러운 보안관제 업무 흐름으로 연결되도록 제작해 주세요.
